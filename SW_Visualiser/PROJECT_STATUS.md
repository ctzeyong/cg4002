## 1. What the project is

CG4002 capstone: a 2-player AR tower-defence game called **Bridge Rush** (formerly "Battle Cats AR"). Each player carries a phone and a glove with a gesture sensor.

- The **Ultra96** classifies glove gestures and publishes them over MQTT.
- Each **phone** (the Software Visualiser, this folder) renders the match in AR over the camera feed.
- Each player wears an **AprilTag**. A phone can't see its own player's tag, so it tracks the *opponent's* tag and builds the arena between the two devices.
- Players summon units (Warrior, Rogue, Mage, Tank, Hero) and two spells. Units cross a bridge, fight on contact and hit the enemy tower.

Game rules (see `Game_logic.md` if it still exists):

- Mana caps at 10, starts at 5 and regenerates at 1 per second (code default and requested value from 2026-10-27; the scene saves its own, set it in the Inspector). Lightning costs 5 and Fireball 6. In the last 60 seconds mana regenerates at double speed (a "2x MANA!" banner announces it).
- A rejected gesture costs nothing.
- Summon cost is flat per unit type (`MatchState.GetManaCost`). **Intentional:** there is no surcharge for summoning near the bridge. A unit summoned closer to the bridge arrives sooner, and that placement choice is part of the strategy (decision 2026-10-22, see Week11.md section 11). Do not add a surcharge.
- A match ends when a tower reaches 0 HP or the timer runs out. Higher tower HP wins on timeout. The timer is 180 s today (the original design was 5 minutes).

Design decisions that still hold:

- **Host and client.** Player 1's phone is the host and runs `MatchState`. Player 2's phone is a client that mirrors the host's `game/state` snapshots and sends spawn requests. VS CPU stays local with a random enemy bot. This stands in for the missing authoritative backend.
- **Canonical positions.** Unit positions cross the network as `along`/`lat` fractions of the lane, never raw world coordinates, because the two phones' AR sessions don't share a coordinate space.
- **Towers follow the player.** A Lock Tower button freezes a tower during setup. It unlocks when the match starts.
- **Bridges and arena.** Two islands joined by two parallel bridges (`MatchState.twoBridges`, default on; off gives the old single centre bridge). Each unit picks the nearest bridge once (`UnitState.BridgeIndex`). The arena boundary is the union of the funnelling island and the two bridge strips (`FunnelBlend`, `ClampLateral`). The summon zone is a separate, simpler full-island-width rectangle.
- **Fixed pre-bridge route.** Units steer against a home-anchor axis captured at match start. They home on the live tower only after clearing the bridge. This stops units being dragged when a player walks.
- **No `IMatchState` interface.** There was one implementation, so it was dropped. Re-extract it if a real second implementation (an Ultra96-backed state) appears.
- **Comms files are read-only here.** `Envelope`, `SeenEvents` and `MqttConfig` are fixed in the comms repo and copied across.

## 6. Setup facts and gotchas

- Unity `6000.5.9f1`. AR Foundation and ARKit/ARCore 6.5.0, XRI 3.5.1, URP 17.0.3, Input System 1.19.0, Newtonsoft 3.2.2. `jp.keijiro.apriltag` comes from GitHub.
- Portrait only. `AprilTagTracker` rotates the camera image 90 degrees to match.
- An iOS device build needs a full Unity **Build Profile, iOS, Build**. Re-running Xcode on a stale `ios-build/` picks up nothing. Set the bundle identifier and camera usage description in Player Settings, not in Xcode.
- Edits made in Play mode don't persist. Close and reopen the scene after file-level edits.
- One compile error anywhere blocks every script from registering as a component.
- Testing PvP needs two phones plus a broker on the same network (for example `mosquitto -v` on a laptop).
- Rosetta 2 is needed on Apple silicon for Google's `arcoreimg` (the Android build errors `Unable to score image` and `BuildDatabaseFailedException`) and for Cisco's ThousandEyes module. Installed 2026-10-20 with `softwareupdate --install-rosetta --agree-to-license`.
- Comms tunnel facts: the first hop uses the SoC account username (not the NUSNET email) and its password; the second hop is the board's shared lab login. The board host has a dot before `ddns` (`...-43.ddns...`); a dash typo made hop 2 fail with `closed before a valid SSH identification string`. The phone needs the NUS VPN. Keep credentials and real hostnames out of the repo and docs.
- `MqttConnection` Connect On Start must stay off with the tunnel, and a broker host saved from the debug menu (`broker_host.txt` on the phone) overrides the Inspector value, so keep it `127.0.0.1`. The debug menu's broker field and direct MQTT Connect are gone (2026-10-20); use its Comms category.
- `AiGestureHook` and `GloveGestureReceiver` subscribe to the same `game/gesture/N` topic and `MqttConnection` keeps one handler per topic, so use only one of them in a scene.
- Mac VPN: Cisco Secure Client is not working on the dev Mac yet (partial installs left package receipts; remove them with `pkgutil --forget`, restart, then install only the AnyConnect VPN module). A Linux machine on the VPN is used to SSH to the board for the `mosquitto_sub` and `ev` test commands.
- Unity was building for Android at one point (Build Profile); make sure it matches the phone under test.
- To test the glove path without hardware, use `mqtt_client.py --publish-every` from `Comms/laptop`.
